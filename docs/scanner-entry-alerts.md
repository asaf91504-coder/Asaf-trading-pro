# Scanner entry alerts
Integrated with the current authenticated POST scan-market handler and the existing account alert inbox. Uses provider-owned records only; clients cannot submit qualifying status. Baseline is silent. Unknown data preserve state. Closed sessions are processed once; retries and concurrent scans use one Redis Lua transaction for state and inbox. Existing account deletion clears these keys; the Lua member-record guard prevents resurrection after deletion or account changes.

Fixed version scanner-entry-v1: USD market cap >=1B, close >5 and MA20, existing scanner risingVolume definition (close above previous close and last volume above previous twenty-session mean), and a long pattern candidate at crossed stage. These are heuristic candidates, not independently confirmed predictions. MA150 and ATR are informational. This fixed alert preset is separate from editable UI scan filters. First valid scan and new rule versions establish a silent baseline. Corrected already-processed sessions do not generate new events.

Runs after explicit provider scans, not on a new automatic schedule. No extra market API calls, subscriptions or provider activation added. Events appear in the existing dailyAlerts inbox when loaded. Returns scannerAlerts.added/unavailable in the scan response; alert storage failure does not discard successful market results. Background daily scanning remains a separate integration: the existing background price-crossing worker is unchanged.

Validation: node --test tests/*.test.mjs. Lua transaction additionally executed against fakeredis with Lua support: 10 concurrent submissions create exactly one alert; tested continuation, reentry, version reset, stale sessions and deleted account. This emulator test is not a production Upstash test. Live provider end-to-end validation is pending licensed data activation.
